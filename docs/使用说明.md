# 使用说明（业务同学版）

> 面向运营、采购、客服同学：不需要懂代码，按下面步骤就能每天拿到报表、处理数据问题。

## 一、第一次使用

1. 安装 Python 3.11 及以上版本（安装时勾选 `Add Python to PATH`）。
2. 在项目目录打开终端，执行：

```bash
pip install -r requirements.txt
python main.py run
```

3. 看到「跑批完成」即成功。此时：

- 报表在 `output/` 目录，文件名形如 `ecom_daily_report_20261022_1447.xlsx`
- 打开内部工具页面：`python main.py serve`，浏览器访问 <http://localhost:8501>

## 二、每天怎么用

### 方式一：手动跑一次（1 分钟）

双击或在终端执行 `python main.py run`。

### 方式二：定时自动跑（推荐）

Windows（任务计划程序）：

1. 新建基本任务，触发器设为每天 08:30；
2. 操作选择「启动程序」，程序填 `python`，参数填 `main.py run`，起始位置填项目目录（如 `C:\Users\你\Desktop\auto`）。

Linux / macOS（cron）：

```bash
30 8 * * * cd /path/to/auto && /usr/bin/python3 main.py run >> logs/cron.log 2>&1
```

也可以直接常驻：`python main.py schedule --at 08:30`（终端需保持打开）。

## 三、报表怎么看

打开 Excel，按 Sheet 从左到右看即可：

1. **经营概览**：先看这几张卡。GMV 和订单环比下降超过 15%，先想是不是大促节奏变化；退款率突然上升，去「异常清单」看是否已有告警。
2. **日销售趋势**：看拐点。曲线突然掉下去，通常是数据断档或活动结束，不要直接当成生意变差。
3. **平台表现 / 品类表现**：比较「GMV 占比」和「毛利率」——高占比低毛利的品类是优化重点。
4. **SKU排行**：A 类商品贡献 70% GMV，是备货和投放重点；C 类可以尝试清仓。
5. **库存预警**：重点看三列——状态、可售天数、建议补货。可售 < 7 天就要当天下采购单。
6. **活动效果**：看「提升幅度」而不是只看 GMV。活动期 GMV 高，但基准期本来就高，说明活动没带来增量。
7. **推广效果**：ROI < 1 的渠道直接控预算；CTR 正常但 CVR 低，问题多半在详情页或价格。
8. **数据质量**：如果这天数字看着不对，先来这里看「采集日志」是否失败、「清洗日志」命中了多少行。
9. **异常清单**：见下一节。

### 口径说明（重要）

- GMV = 支付成功 + 已退款订单的实付（按支付时点）
- 净销售额 = 支付成功实付 - 退款
- 退款率 = 退款金额 / GMV
- 毛利率 =（实付 - 成本 × 数量）/ 净销售额
- 可售天数 =（现有 + 在途）/ 近 30 天日均销量

口径集中写在 `src/ecom_ops/metrics.py`，和页面、AI 问数完全一致。如果业务口径变了，改一处即可，不要在各处手写公式。

## 四、异常中心怎么处理

打开页面 →「异常中心」标签，或命令行 `python main.py issues`。

每条异常包含：规则、等级（高/中/低）、描述、定位（哪天的哪个平台/SKU）、累计出现次数、状态。

处理流程：

| 状态 | 含义 | 什么时候用 |
|---|---|---|
| 待处理 open | 系统新发现 | 默认状态 |
| 处理中 acked | 已认领，正在处理 | 已联系平台/仓库，等待补数或到货 |
| 已修复 fixed | 问题已解决 | 补数完成、商品档案补齐、库存已补货 |
| 已忽略 ignored | 确认无需处理 | 例如内部测试单、活动造成的合理波动 |

在页面表单里填工单号 + 目标状态 + 备注即可；命令行：

```bash
python main.py issues --status open --level high
python main.py issues --set DQ0A1B2C3D4E --to acked --note "已联系平台补数，今天 18:00 前完成"
```

**注意**：同一个问题再次出现，系统只累加「累计次数」，不会覆盖你已经填写的状态和备注。

### 14 条规则分别代表什么

| 规则 | 含义 | 通常怎么处理 |
|---|---|---|
| R001 源数据重复 | 平台重复导出/重复推送 | 确认导出任务未重复执行；系统已去重，需确认没有漏单 |
| R002 订单商品无主数据 | 有订单没有商品档案 | 补 SKU 档案（品类、成本），否则毛利不准 |
| R003 金额勾稽不平 | 实付 ≠ 单价×数量-优惠 | 核对优惠分摊，差额大的订单人工复核 |
| R004 推广归因偏差 | 归因 GMV 与订单 GMV 差太多 | 检查归因窗口、跨平台去重 |
| R005 下单时间异常 | 时间为空或晚于今天 | 检查时区/字段映射，避免污染当日 GMV |
| R006 数据断档 | 连续 N 天无数据 / 流量表缺失 | 查看采集日志，补数后重跑 |
| R007 库存为负 | 超卖或回传延迟 | 冻结可售库存，核对仓库实盘 |
| R008 库存预警 | 断货或可售不足 3 天 | 当天补货，爆款优先 |
| R009 库存滞销 | 45 天无动销且压货 | 清仓/捆绑，暂停补货 |
| R010 负毛利订单 | 折扣叠加导致亏损 | 检查活动折扣与成本口径 |
| R011 退款率超阈值 | 周维度或 SKU 维度偏高 | 抽查退款原因，同步客服与详情页 |
| R012 活动未达预期 | ROI 低于目标 | 复盘选品与投放 |
| R013 零金额支付单 | 赠品/内部单混入 | 从销售分析中标注剔除 |
| R014 订单状态未识别 | 平台新增了状态文案 | 在 `config.yaml` 的 `clean.status_map` 里补充 |

## 五、换成真实数据

### 1. 上传文件

页面「数据接入」标签 → 选择数据类型 → 上传 CSV。文件会保存为 `data/raw/orders.csv` 等，然后点左侧「立即跑批」。

### 2. 表头对不上怎么办

系统已内置常见中文表头识别（订单编号/订单号、实付金额/买家实付、商品编码/商家编码……）。如果平台表头比较特殊，在 `config/config.yaml` 对应数据源下加映射：

```yaml
ingest:
  sources:
    - name: orders
      type: csv
      file: data/raw/orders.csv
      rename:
        订单主键: order_id
        成交时间: order_time
```

### 3. 从 CSV 换成 Excel

```yaml
    - name: orders
      type: excel
      file: data/raw/orders.xlsx
      sheet: 订单明细
```

### 4. 从文件换成接口

```yaml
ingest:
  api:
    enabled: true
    base_url: http://127.0.0.1:8801
    paths:
      orders: /api/v1/orders
      inventory: /api/v1/inventory
```

接口需要按分页返回 `{"data": [...], "has_next": true}`。可以先运行 `python main.py mock-api` 体验。

### 5. 调整阈值

在 `config.yaml` 的 `validate.thresholds` 里改，例如把退款率阈值从 8% 调到 10%，下次跑批即生效，不用改代码。

## 六、常见问题

**跑批报「缺少必需列」**
平台导出多了一列或少了一列。按提示里的「实际列」对比 `config.yaml` 的 `required_columns`，缺什么补什么，或在 `rename` 里做映射。

**时间解析失败很多行**
把报错时的样本时间贴给数据负责人，在 `src/ecom_ops/clean.py` 的 `DATETIME_FORMATS` 里加一种格式即可。

**平台名变成了「其他」**
在 `config.yaml` 的 `clean.platform_map` 里补充新平台的别名。

**页面打不开**
确认终端没有报错；端口被占用时换一个：`python main.py serve --port 8502`。

**报表数字和平台后台对不上**
先看「数据质量」页的采集日志（是否少拉了一天）和清洗日志（是否去重了重复行），再核对口径表。差异通常来自：退款是否计入 GMV、是否包含未支付订单、时间边界含不含当天。

**想重新来一遍**
删除 `db/ecom.db` 和 `output/` 下的旧文件，重新执行 `python main.py run`。原始数据在 `data/raw/` 不会被删。
